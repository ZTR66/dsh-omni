# 视频要点

介绍 dsh-omni 时，这些功能必须讲到。

---

## 一、视频理解（核心，讲透）

**必须演示真实效果**：丢一个没看过的视频进去，让它说出内容。

要讲的点：

1. **宫格扫描** — 视频切成带时间码的格子，一次看全片结构
2. **采样密度可调** — `fps`、`cellWidth`、`from`/`to`、`grid` 都是参数
3. **AI 自己决定看多细** — 先概览找结构，再局部加密，最后抽单帧
4. **返回时间轴** — 格子编号对应精确秒数，能引用、能回溯
5. **精确抽帧** — 解码到指定帧，不是跳到关键帧

**要强调的对比**：不是固定截 9 帧，不是按镜头切分。看多细由 AI 判断。

---

## 二、音频理解

要讲的点：

1. **给数字不给形容词** — BPM、节拍规律性、调性、频谱质心、过零率、响度、每秒能量
2. **检测不到就说检测不到** — 环境声、人声、自由节奏的曲子会返回"未检测到节拍"，不硬编数字
3. **能做配乐决策** — 拿这些数字卡点、选素材、判断明暗

**说明边界**：不做乐器分类。

---

## 三、语音

要讲的点：

1. **转写** — 带时间码，支持云端和本地两种通道
2. **本地优先** — 不需要联网、不需要 API Key，首次使用自动下模型
3. **合成** — 文字转语音，返回实测时长和字每秒语速
4. **自动识别环境** — 有宿主识别器就用，没有就回退本地

---

## 四、图片生成

要讲的点：

1. **多服务适配** — 一套调用支持 8 类服务（OpenAI、Gemini、硅基流动、火山、智谱、百炼、Mona、本地 A1111）
2. **各服务差异被抹平** — 尺寸字段、返回格式、轮询协议都不同，调用方看到的是一套
3. **尺寸自动适配** — 模型不支持的比例会吸附到最近的合法尺寸，并告诉你调整了
4. **设置页可配** — 不写代码，界面上加服务、填密钥

---

## 五、视频生成（重点讲"限制"）

**这部分是全片最该讲的，因为它和别的插件不同。**

要讲的点：

1. **能力判定** — 代码能画的场景（文字、图表、几何、转场、界面演示）直接拒绝，不看占比
2. **给替代方案** — 拒绝时告诉你可以用什么工具、成本多少
3. **需要授权** — 通过的场景还要用户确认，或用户明确要求
4. **没有审批服务就拒绝** — 无人值守环境不自己决定花钱
5. **成本对比** — 60 秒全 AI 生成约 ¥25，代码渲染 ¥0

**要强调的逻辑**：不是"我能生成"，而是"我知道什么时候不该生成"。

---

## 六、视频组装

要讲的点：

1. **图片 + 音频 → MP4** — 静帧按时长排好，配音铺在下面
2. **素材混合** — 静帧、已有片段、音频可以任意组合
3. **输出即用** — H.264 + AAC，参数固定，不用二次转码
4. **代码路径零成本** — 能用代码画的镜头走这条，改一次重渲一次都不花钱

**这是"省钱的正确做法"**，和第五条呼应。

---

## 七、通用能力

要讲的点：

1. **媒体探测** — 容器、时长、码率、编码、分辨率、帧率、帧数、采样率、声道
2. **环境检测** — 检查 ffmpeg、Python 库、Whisper 模型、本地生成服务，缺什么给安装命令
3. **音轨提取** — 从视频里取音频，交给转写或分析


---

## 八、安装与配置

要讲的点：

1. **一行安装** — `dsh plugin add @ztr66/dsh-omni`
2. **设置页** — 设置 → 全模态，图形界面配服务
3. **密钥安全** — 填的密钥自动移进凭据库，配置文件里不留明文
4. **依赖提示** — 缺 ffmpeg 或 Python 库时，检测报告会给具体安装命令

## 一句话总结（可做结尾或简介）

> 一个 DSH 插件，让 AI 真正能看视频、听音频、生成图片和视频。
> 关键不是它全能，而是它知道什么时候不该用 AI。
